# 005 — Ontology index; no prefix registered

## PR

### Summary

The package moves to core's ontology module layout and registers no prefix: an app lists the
prefixes it uses in its own prefix map.

- `src/ontologies/owl.ts`: regenerated by `linked generate-ontology`; each term is `export const X = {id: '<full IRI>'}`, the module imports nothing.
- `src/ontologies/index.ts` (generated): registers owl (77) with `registerOntologies([...], import.meta.url)`: name, namespace, terms, data files, suggested prefix. The entry and `src/shapes/index.ts` import it.
- Removed: `owl.data.ts`, `owl.register.ts` (`ns`, `dataFiles`, `loadData`, `_ontologyResource`, and the prefix they added). `src/package.ts` exports `registerOntologies` instead of `linkedOntology`.
- `Ontology.prefix` reads the app's prefix map (the map in use); its doc comment and the README say so and name `Prefix.getPrefix(o.id, map)` for another map. The README no longer calls `prefix` the SHACL declaration (that is `declaredPrefix`). `ontologies/metadata-terms` (VANN, ADMS, schema.org terms by IRI) is unchanged and not registered: those are not this package's ontologies.
- `test/app-prefix-map.test.mjs` (new): loading the package adds no prefix for the OWL namespace; with `Prefix.load({owlx: OWL})` the getter returns `owlx`; an explicit map works through core.
- `test/shape-check.test.mjs` imports `ontologies/index.js` (own and dependencies') instead of the `.register.js` modules.
- README: the module paragraph describes the index, terms as literals, no prefix registered, and core's `createNameSpace` for a namespace function.
- Changeset `.changeset/ontology-index-no-prefix.md` (major), beside the pending patch from the vann step.
